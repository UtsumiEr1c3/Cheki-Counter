## Context

当前所有切奇单价均以 Dart `int` 和 SQLite `INTEGER` 保存，但各录入入口及服务层统一要求大于 0。支出页只查询聚合值，页面没有能跨偶像、跨活动展示切奇的全局明细入口。

## Goals / Non-Goals

**Goals:**

- 让所有新建切奇路径一致接受 0 元单价，数量继续要求大于 0。
- 让六个切奇支出项按当前年份和所选分类下钻，并提供到既有详情页的后续导航。
- 保持 CSV、聚合统计和已有整数数据兼容。

**Non-Goals:**

- 不支持小数金额或负数金额。
- 不增加切奇编辑页、单条切奇详情页或门票支出下钻。
- 不调整现有统计口径。

## Decisions

### D1：保留整数金额存储

切奇单价校验由正整数改为非负整数，模型和数据库字段保持 `int/INTEGER`。

为什么：0 已能由当前模型、乘法和聚合查询正确表示，无需数据库迁移。候选方案是同时改为小数金额，但会扩大到模型、数据库、CSV、格式化及全部统计页面，当前已明确暂缓。

### D2：使用一个筛选模型承载六种下钻条件

记录仓库新增统一明细查询，接受年份，以及可选的切奇类型或参与方式条件。六个支出项分别映射为：全部、`normal`、`theme`、`group`、现场、在线。

为什么：各分类共享查询字段和列表布局，可避免重复仓库方法与重复页面。查询通过 JOIN 补齐偶像名、活动名和活动 ID。

### D3：新增统一切奇明细页

支出项点击后打开同一个明细页。列表行直接展示类型、对象、日期、数量、单价、小计、参与方式和活动名；主题切以偶像名为标题，并在明细信息中展示主题名；有 `event_id` 时点击进入 `EventDetailPage`，否则有 `idol_id` 时进入 `IdolDetailPage`。团切按既有约束始终关联活动。

为什么：现有偶像详情和活动详情都只能覆盖单一对象，无法作为跨对象聚合项的第一层下钻。候选方案是切换活动页签，但会遗漏无活动记录和主题切。

### D4：只让切奇金额条目可点击

本次为“全部切奇费用”、三种类型和两种参与方式增加点击与尾部箭头；累计支出、现场活动门票和现场参加保持汇总展示。

为什么：本次需求明确聚焦几类切奇，避免顺带引入另一套活动贡献筛选语义。

## Risks / Trade-offs

- [风险] 多个录入入口可能遗漏校验调整 → [缓解] 覆盖普通切、新建偶像首条切、活动个人切、主题切、团切和 CSV 的单元或组件测试。
- [风险] 明细金额合计与入口汇总不一致 → [缓解] 明细查询复用聚合查询的年份、类型和 `is_online` 条件，并增加查询结果合计断言。
- [风险] 0 元记录在列表中看起来像无数据 → [缓解] 明细仍展示记录并明确显示小计 `¥0`，空态只依据记录数量判断。

## Migration Plan

无需数据库迁移。升级应用代码后，已有数据保持不变；回滚版本也不会遇到新字段或新数据类型。
