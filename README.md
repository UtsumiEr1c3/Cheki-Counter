# Cheki Counter

Cheki Counter 是一个用 Flutter 编写的离线记账工具，用来记录偶像切奇（cheki）、主题切、活动团切和门票支出，并提供活动、偶像、团体和支出视角的汇总分析。

项目当前的核心特征是：

- 本地 SQLite 存储，无后端、无登录、无云同步
- 通过 CSV 做手动备份、迁移和合并导入
- 以 Android 使用场景为主，仓库保留了 Flutter 默认多端脚手架
- 支持普通切、主题切和单团/联合团切，并区分现场与电切
- 当前应用版本为 `1.3.2`

## 功能概览

- 首页用卡片网格展示所有已有记录的偶像，并显示总切数、偶像数、总金额
- 支持为已有偶像追加切奇记录，单价会默认带出该偶像最近一次记录的价格，并允许记录免费切（单价为 `0`）
- 支持新建偶像，同时要求录入第一条切奇记录
- 支持预设应援色、调色盘和 `#RRGGBB` Hex 输入；偶像详情页可编辑名字、应援色和团体
- 支持添加主题切，也可将已有的无活动普通记录标记为主题切
- 支持新建活动，即使该活动暂时没有关联任何切奇记录也可以单独保存
- 活动支持编辑名称、日期、场地、门票价格和参与方式，并可在详情页添加个人切或团切
- 团切可关联一个或多个团体，保存当次成员快照，并在各参与团体的统计中分别归属
- 偶像详情页提供总览、按日/按月折线图、历史记录列表和单条删除
- 偶活总览支持年份及现场/电切筛选；支出页按切奇类型和参与方式汇总，并可下钻到记录明细
- 统计页提供个人与团体的切数/金额排行、年份筛选和团体详情
- 设置页提供 CSV 导入、CSV 导出和团体总览入口
- 支持“现场 / 电切”记录和活动；仅电切活动不计入现场参加场数与门票支出

## 代码架构

### 1. 入口与状态管理

- `cheki_counter/lib/main.dart`
  - 启动时先初始化 SQLite 数据库
  - 使用 `provider` 注册 `IdolListNotifier`
- `cheki_counter/lib/app.dart`
  - 定义首页、统计页、设置页、团体总览页和偶像详情页路由

### 2. 数据层

- `data/db.dart`
  - 负责数据库创建与升级
  - 当前 schema 版本为 `10`
  - 表结构包括 `idols`、`events`、`records`、`record_groups`
- `data/models/`
  - `idol.dart`：偶像实体与聚合字段
  - `event.dart`：活动实体
  - `record.dart`：切奇记录实体
- `data/*_repository.dart`
  - `IdolRepository`：偶像查询、聚合、新偶像和首条记录的事务写入
  - `RecordRepository`：普通切、主题切和团切的写入与查询，以及删除、场地归一化和支出明细
  - `EventRepository`：活动 upsert、编辑、参与方式、活动摘要和支出聚合
- `data/csv_service.dart`
  - 负责 CSV 导入导出
  - 处理 BOM、兼容旧版列格式、去重、错误汇总和导出文件生成

### 3. UI 分层

- `features/home/`
  - 首页、偶像卡片、新建偶像、新增普通切和主题切
- `features/idol_detail/`
  - 偶像详情、折线图、记录删除
- `features/events/`
  - 活动新建/编辑、活动总览、活动详情、个人切/团切录入和支出明细
- `features/statistics/`
  - 总体统计页、团体总览页、团体详情页
- `features/settings/`
  - CSV 导入导出、团体总览入口
- `shared/widgets/`
  - `VenueField`：历史场地下拉 + 输入过滤
  - `EventField`：历史活动下拉 + 自动带出日期/场地/门票价格

## 数据模型与业务规则

### 偶像

- 业务唯一键是 `(name, color, group_name)`
- 可在偶像详情页编辑名字、应援色和团体；若与另一位偶像形成相同的业务唯一键，保存会被拒绝
- 每位偶像还有不可变的 `stable_id`，用于 CSV 导入导出时识别同一偶像；修改资料不会改变该标识
- 应援色名称和实际 ARGB 色值分别保存，颜色名称参与业务唯一性判断，实际色值用于界面渲染
- 偶像必须至少有一条记录；删除最后一条记录时会连带删除该偶像

### 活动

- 业务唯一键是 `(name, venue, date)`
- 每个活动还有不可变的 `stable_id`，用于编辑后的 CSV 往返识别
- 活动可以独立存在，不要求必须挂接记录(即只看不特)
- 活动可记录 `ticket_price` 门票价格；历史数据和未填写时默认为 `0`
- 活动参与方式分为“现场参加”和“仅电切”；仅电切活动不计入现场门票支出与参加场数
- 活动详情可编辑活动资料并添加个人切或团切；当前没有活动删除 UI

### 切奇记录

- 记录类型包括 `normal`（普通切）、`theme`（主题切）和 `group`（团切）
- 公共字段包括日期、数量、单价、小计、场地、创建时间、可选活动和是否电切
- `subtotal` 按 `count * unit_price` 持久化保存
- 数量必须是正整数，单价允许为 `0` 的非负整数
- 新建记录时：
  - 既有偶像默认继承最近一次单价
  - 新偶像默认单价为 `60`
  - 可选绑定活动；绑定活动时可填写门票价格，若已有活动门票为 `0` 且本次填了正数，会补写到该活动
  - 可标记为电切
- 主题切关联单个偶像、保存主题名称，且不关联活动
- 团切关联活动和一个或多个团体、保存成员快照，不关联单个偶像；无论关联多少团体，在活动与整体支出中只计算一次

### 电切

- `records.is_online = 1` 表示电切记录，`events.is_online = 1` 表示仅电切活动
- 线上记录仍计入偶像详情页和全局统计
- 偶活总览可分别筛选现场活动、仅电切活动或全部活动

### 场地归一化

- 手动录入场地时会做 `trim()` 和大小写归一化匹配
- 如果历史中已存在仅大小写不同的同名场地，会复用已有写法
- CSV 导入不会做这一步归一化，而是按文件原始值导入

## CSV 说明

### 导出格式

当前导出采用固定 22 列：

```text
偶像ID,偶像名,应援色,团体,日期,数量,单价,小计,场地,创建时间,活动名,活动场地,活动日期,电切,门票价格,应援色值,活动ID,活动方式,切奇类型,切奇名称,团切成员,团切团体
```

说明：

- 编码为 UTF-8 BOM，便于在 Excel 中直接打开
- `偶像ID` 和 `活动ID` 是稳定 ID。导入时会优先用它们匹配已有数据，以便资料编辑后的备份仍能正确合并
- `应援色值` 使用 `#RRGGBB` 保存自定义颜色
- `切奇类型` 区分普通切、主题切和团切；联合团切的全部团体以 JSON 数组保存在 `团切团体`
- 会同时导出普通记录、关联活动的记录，以及没有关联记录的纯活动行
- 会导出活动参与方式、主题名称、团切成员快照和全部团体关联
- 有活动的行会导出该活动的门票价格；无活动的 legacy 记录门票价格留空
- 导出时按演出日期倒序排列

### 导入规则

- 导入语义为“合并追加”，不会清空现有数据库
- 支持兼容旧版 9/11/12/13/14/15/16 列格式，并按表头识别当前扩展格式
- 优先按稳定 ID 复用偶像和活动；旧格式回退到偶像/活动业务唯一键
- 普通切、主题切和单团/联合团切都支持导入导出
- 旧格式或门票价格空白时按 `0` 处理；无效门票价格会记录错误并按 `0` 兜底
- 导入会按记录公共字段和类型专属字段去重：

```text
(idol_id, date, count, unit_price, venue, created_at, event_id, is_online,
 record_type, special_name, group_name, group_members, group_names)
```

其中主题切使用主题名称参与去重，团切还会比较完整且有序的参与团体列表。

- 单行失败不会中断整体导入，最终会汇总新增、跳过和错误数

## 使用方法

### 环境准备

建议准备：

- Flutter SDK
- Android SDK / Android Studio
- 可用的 Android 模拟器或真机

先在项目应用目录安装依赖：

```bash
cd cheki_counter
flutter pub get
```

### 本地运行

```bash
cd cheki_counter
flutter run -d android
```

如果你已经连接好设备，也可以直接：

```bash
cd cheki_counter
flutter run
```

### 构建 APK

```bash
cd cheki_counter
flutter build apk --release
```

如果需要按 ABI 拆包：

```bash
cd cheki_counter
flutter build apk --release --split-per-abi
```

## 典型使用流程

1. 首次使用时，在首页右下角 `+` 新建偶像，并录入第一条记录
2. 后续可直接在偶像卡片右上角追加记录
3. 如果某次活动暂时没有切奇，也可以单独新建活动
4. 从首页添加主题切，或在活动详情中添加个人切、单团体团切和联合团切
5. 在“偶活总览”筛选现场/电切活动，并在“支出”页查看分类汇总和记录明细
6. 在“统计”和“团体总览”中查看个人、团体的占比与排行
7. 在“设置”中导出 CSV 备份，或导入 CSV 合并旧数据

- 项目本身不依赖在线服务，数据默认保存在本地 SQLite
- `csv/` 目录被 `.gitignore` 忽略，适合放个人导入导出文件，但不应提交真实私有数据
- README 不应记录任何个人路径、账号、设备信息、活动私密数据或样例导出内容

## 当前限制

- 没有登录、同步、多端合并冲突处理
- 没有切奇记录编辑，只支持新增和删除
- 没有活动删除界面
- 自动化测试尚未完善
- 仓库虽然保留多平台脚手架，但当前主要使用路径和文档以 Android 为准
